## 1. 功能概述

### 1.1 目标

为 App 内书架提供**快速检索目标书籍**的能力，让用户无需翻页就能瞬间定位到想找的书。

### 1.2 核心场景

| 场景 | 用户需求 | 当前状态 |
|------|----------|----------|
| 书架有 50+ 本书，想找某本 | 在书架页顶部直接搜索 | ✅ 已实现（v1.2 书架内嵌搜索栏，支持防抖实时搜索） |
| 只记得作者名，不记得书名 | 按作者搜索 | ✅ 已实现（v1.2 后端 + 前端均支持书名 & 作者双字段搜索） |
| 记住部分书名（如"剑"开头） | 模糊匹配 + 实时建议 | ✅ 已实现（客户端 LIKE 过滤 + 服务端 LIKE，2 字符触发，300ms 防抖） |
| 快速访问最近在读的书 | 一键跳转或置顶展示 | ✅ 已实现（Ctrl+K 命令面板展示最近阅读 + 标记置顶） |
| 键盘重度用户 | Ctrl+K 命令面板 | ✅ 已实现（v1.2 全局快捷键，类 VS Code 快速打开） |

## 3. 实现方案（回顾）

### 3.1 方案选型：混合方案（A + B）— 已落地

**核心思路**：书架页首次加载时全量获取用户的所有书籍（page_size=200），后续搜索/筛选在前端内存中完成，实现**零延迟过滤**。当用户书架 > 200 本时，自动切换为后端搜索模式。

此方案已在 v1.2 中完整实现，并在 v1.3 中扩展了 AI 语义搜索能力。

### 3.2 已实施的功能（阶段一 + 阶段二，v1.2 完成）

#### 阶段一 ✅：书架页内嵌搜索栏

- `ShelfView.vue`：搜索输入框 + 300ms 防抖 + 搜索模式切换（普通/AI 语义）
- `booksStore (books.ts)`：`allBooks` 全量缓存 + `filteredBooks` 客户端过滤列表 + `clientSearch`/`clientFilter` 方法
- `book_service.py`：`search_books` 已扩展为书名+作者双字段 OR 查询
- 搜索行为：0 字符显示全量 / 1 字符不触发 / ≥2 字符延迟 300ms 搜索 / 清空立即恢复

#### 阶段二 ✅：命令面板 Ctrl+K

- `CommandPalette.vue`：类 VS Code 快速打开面板，支持键盘导航、最近阅读快捷入口、高亮匹配
- `App.vue`：全局注册 Ctrl+K 快捷键（聚焦输入框时不拦截，防止与浏览器冲突）
- 面板数据源：`allBooks` 客户端实时过滤，无输入时展示最近 5 本阅读记录

#### 阶段三 ✅（部分）：AI 语义搜索（v1.3）

- `ai_service.py` + `POST /api/v1/ai/search`：自然语言查询向量匹配
- `ShelfView.vue`：AI 搜索模式切换按钮（🤖 AI 语义）
- `types/index.ts`：`AiSearchResult` 类型（含 match_reason 和 score）

## 6. 风险评估与注意事项

### 6.1 风险

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 书架数据量大时客户端过滤卡顿 | 低 | 设置阈值（200 本），超过自动切服务端搜索 |
| LIKE 查询在大量数据下性能差 | 低 | 个人使用场景，数据量有限；可加 MySQL 全文索引 |
| 搜索与分页的交互逻辑复杂 | 中 | 搜索时重置分页到第 1 页；清空搜索时恢复原始分页 |

### 6.2 注意事项

1. **不要移除现有 SearchView 的外部源站搜索功能** — 那是不同的使用场景（发现新书 vs 查找已有书）
2. **搜索栏应该始终可见** — 不要隐藏在折叠菜单中，用户需要一眼看到
3. **保持筛选标签与搜索的兼容** — "已标记" 筛选 + 搜索关键词应同时生效（AND 逻辑）
4. **预留服务端搜索接口的扩展性** — 后端 `search_books` 方法建议接受可选的 `search_fields: list[str]` 参数
5. **关注移动端体验** — 搜索栏在窄屏下应占满宽度，避免过小
