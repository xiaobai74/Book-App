# 书架快速检索 — 功能概述

> 所属模块: SHELF-001 (书架管理) | 版本: v1.3 | 日期: 2026-08-07 | 状态: 更新反映 v1.2 实现

## 功能目标

为 App 内书架页面提供快速检索目标书籍的能力，让用户无需翻页就能瞬间定位到想找的书。**v1.2 已完成核心实现（书架内嵌搜索栏 + 命令面板），v1.3 新增 AI 语义搜索。**

## 核心使用场景

以下表格列出了书架快速检索需要覆盖的 5 个核心用户场景及其当前实现状态：

| 场景描述 | 用户需求 | 当前状态 |
|------|------|------|
| 书架有 50 本以上书籍，想快速找到某一本 | 在书架页面顶部直接输入关键词进行搜索 | ✅ v1.2 已实现：书架页内嵌搜索栏，支持 300ms 防抖实时搜索 |
| 只记得作者名字，不记得具体书名 | 支持按作者名搜索，不限于书名 | ✅ v1.2 已实现：前端客户端过滤 + 后端 LIKE 均同时匹配书名和作者 |
| 只记得部分书名，如包含"剑"字 | 模糊匹配机制，输入部分关键词即可匹配 | ✅ v1.2 已实现：≥2 字符触发搜索，客户端不区分大小写包含匹配 |
| 想快速打开最近正在阅读的书 | 一键跳转或按阅读时间排序展示 | ✅ v1.2 已实现：Ctrl+K 命令面板无输入时展示最近阅读 + 标记置顶 |
| 习惯使用键盘操作的用户 | 通过 Ctrl+K 快捷键唤起命令面板快速搜索 | ✅ v1.2 已实现：全局 Ctrl+K 快捷键，类 VS Code 快速打开面板 |

## 与其他功能模块的关系

书架快速检索功能位于以下模块的交汇点：

- **书架首页组件** (ShelfView.vue): 搜索栏的直接载体，用户在书架页面即可搜索而无需跳转（✅ 已实现）
- **Pinia 状态管理** (booksStore): 负责缓存全量书籍数据（allBooks），提供客户端过滤能力（clientSearch/clientFilter）（✅ 已实现）
- **后端书架接口** (GET /api/v1/books): 提供全量数据加载接口（page_size=200），用于客户端缓存的初始化（✅ 已实现）
- **后端搜索接口** (GET /api/v1/search): 在书架数据量较大时作为服务端搜索的降级方案，支持书名+作者双字段（✅ 已实现）
- **AI 语义搜索接口** (POST /api/v1/ai/search): v1.3 新增，自然语言查询 + LLM 语义匹配（✅ 已实现）
- **命令面板组件** (CommandPalette.vue): Ctrl+K 全局快捷键唤起，实时搜索 + 键盘导航 + 最近阅读（✅ 已实现）
- **顶部导航组件** (TopNav.vue): 可作为全局搜索入口的挂载点

## 设计原则

书架快速检索与现有的外部源站搜索是两种不同的使用场景，二者需要并存而非替代：
- **书架快速检索**: 在已有书架中查找已知的书籍，定位后直接阅读或管理
- **外部源站搜索**: 在全网小说网站中发现新书，添加到书架后再进行抓取
