# 书架快速检索 — 后续迭代方向

> 所属模块: SHELF-001 (书架管理) | 版本: v1.1 | 状态: 更新反映 v1.3 AI 搜索已完成

## 迭代路线图

书架快速检索的后续迭代分为四个版本，按优先级从高到低排列。v1.3（AI 语义搜索）已完成。

### ✅ v1.3：AI 语义搜索（已完成）

已通过 Dify 工作流 + Embedding 向量匹配实现书架内自然语言搜索。用户在搜索栏切换到 AI 模式后，可以输入自然语言描述（如"最近看的那本修仙小说"），后端通过 AI 模型理解语义后匹配书架中的相关书籍，返回匹配结果含 match_reason（匹配理由）和 score（置信度百分比）。

技术实现：
- 后端新增 ai_service.py + POST /api/v1/ai/search 端点
- 前端 ShelfView.vue 新增 AI 模式切换按钮和搜索进度提示
- types/index.ts 新增 AiSearchResult 类型（book_id, title, author, match_reason, score）
- 详见 docs/dify-knowledge/ 和 backend/dify-workflows/shelf-semantic-search.yml

### 🔮 v2.1：拼音搜索支持

使用 pinyin-pro 这个 JavaScript 库实现中文书名的拼音匹配。用户在搜索框中输入拼音（全拼或首字母）即可匹配到对应的中文书名字段。

典型使用场景：用户想找"剑来"这本书，输入"jianlai"或"jl"都能匹配到。这对于中文输入法切换较慢的用户或使用英文键盘的用户有显著价值。

实施建议：在 clientSearch 和 clientFilter 方法中增加拼音匹配分支，对书名和作者名分别生成全拼和首字母两种形式进行匹配。

### 🔮 v2.2：全文搜索升级

当用户书架数据持续增长时，将搜索后端从 MySQL LIKE 查询升级为更专业的搜索引擎。有两个可选方案：
- 方案 A：使用 MySQL 内置的 FULLTEXT 全文索引和 MATCH AGAINST 查询，无需引入新服务
- 方案 B：引入 Meilisearch 作为轻量级全文搜索引擎，提供更好的中文分词和相关性排序

方案 A 适合数据量中等（数千条）的场景；方案 B 适合需要高质量搜索结果的场景。

### 🔮 v2.3：搜索历史与自动补全

- 搜索历史：localStorage 存储最近 5 次搜索关键词，搜索框聚焦时下拉展示，点击历史记录直接触发搜索
- 搜索建议/自动补全：输入 1-2 个字符即显示匹配书名列表，点击建议项直接跳转到书籍详情

### 🔮 v2.4：语音搜索

面向移动端使用场景，支持用户通过语音输入搜索关键词。技术方案可以使用浏览器内置的 Web Speech API（SpeechRecognition 接口），无需引入第三方服务。用户点击搜索框旁的麦克风图标后开始语音识别，识别结果自动填入搜索框并触发搜索。
