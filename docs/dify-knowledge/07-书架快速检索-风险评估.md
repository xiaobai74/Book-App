# 书架快速检索 — 风险评估与注意事项

> 所属模块: SHELF-001 (书架管理) | 版本: v1.1 | 状态: 更新反映 v1.2/v1.3 实现后的实际风险

## 风险评估（v1.2 实施后更新）

### 风险一：书架数据量大时客户端过滤可能导致页面卡顿

- 风险等级：低
- 当前状态：✅ 已缓解。v1.2 已设置 200 本的阈值常量（CLIENT_SEARCH_THRESHOLD），fetchAllBooks 方法在获取数据后自动判断 total 是否超过阈值，超过则切换 searchMode 为 server。
- 实际影响：个人使用场景极少超过 200 本。

### 风险二：数据库 LIKE 查询在大量数据下性能较差

- 风险等级：低
- 当前状态：✅ 风险可控。在客户端模式下完全不走数据库搜索；仅在服务器模式（>200 本）且用户主动搜索时才触发 LIKE 查询。数据量小，性能问题实际不会出现。
- 未来方案：如确实需要优化，可添加 MySQL FULLTEXT 索引或引入 Meilisearch。

### 风险三：搜索与分页的交互逻辑较复杂

- 风险等级：低（原中 → 已降低）
- 当前状态：✅ 已解决。v1.2 实现中，客户端搜索时 filteredBooks 完全替代分页显示，搜索过程中书架列表直接转为过滤结果视图。清空搜索时恢复全量书架和正常分页。AI 搜索模式下分页组件自动隐藏。

### 风险四：全量数据加载与现有分页接口的兼容性

- 风险等级：低
- 当前状态：✅ 已解决。allBooks 和 filteredBooks 是两个独立的新状态，不修改现有的 books 数组。ShelfView.vue 通过 displayBooks 计算属性动态切换数据源，不影响其他页面使用 booksStore。

### 风险五：AI 语义搜索响应时间较长

- 风险等级：中（v1.3 新增）
- 当前状态：⚠️ AI 语义搜索通常需要 5-15 秒，期间输入框禁用并显示进度动画和文字提示，避免用户重复点击。如果 Dify 工作流服务不可用会显示友好错误提示。
- 缓解措施：搜索按钮旁明确标注"AI 语义"，设置合理的 HTTP 超时时间，提供清晰的加载状态反馈。

## 实施注意事项（v1.2 已落地）

### ✅ 不要移除现有搜索功能
SearchView.vue 的外部源站搜索功能解决的是"发现新书"的需求，与书架快速检索的"查找已有书"是不同的使用场景，两者已并存。
实际实现中通过独立的 searchBooks 和 searchBooksExternal 两个 API 函数 + SearchView 的两个标签页确保两者完全独立。

### ✅ 搜索栏必须始终可见
搜索栏已直接嵌入书架页面主体区域，固定在标题下方，随页面滚动。当书架为空且无搜索关键词时搜索栏隐藏（v-if="booksStore.bookCount > 0 || searchKeyword"），避免空白页面出现无意义的搜索框。

### ✅ 筛选标签与搜索应同时生效
当用户同时设置了筛选条件（如"仅已标记"）和搜索关键词时，两个条件取 AND 逻辑。在 clientFilter 方法中通过多层 filter 链式调用实现。AI 语义搜索模式下筛选标签自动隐藏（数据源不是本地数组，无法做组合筛选）。

### ✅ 预留服务端搜索接口的扩展性
后端 search_books 方法已使用 or_ 函数，未来如需添加更多搜索字段（如 source_url、分类标签），只需在 or_ 条件中追加新的 LIKE 表达式即可。

### ✅ 移动端体验
搜索输入框在屏幕宽度小于 768 像素时占满整行（通过 CSS flex-wrap 实现）。命令面板使用相对视口宽度。筛选标签使用 el-radio-group 自动折行。命令面板中的结果条目最小触摸区域满足 44px 标准。

### ✅ 快捷键不要与浏览器冲突
Ctrl+K 在 Chrome 和 Edge 浏览器中是聚焦地址栏的默认快捷键。v1.2 的实现中，onGlobalKeydown 会在检测到焦点元素为 input 或 textarea 时直接 return，不拦截事件。这意味着在搜索页面的输入框中按 Ctrl+K 时，浏览器正常聚焦地址栏；在其他区域按 Ctrl+K 时，弹出命令面板。
