# 书架快速检索 — 实施步骤

> 所属模块: SHELF-001 (书架管理) | 版本: v1.3.2 | 状态: 更新反映 v1.2/v1.3 已完成的实施 + v1.3.2 搜索触发方式调整

> **v1.3.2 变更说明**：搜索触发方式已由防抖自动搜索改为点击「搜索」按钮 / 按 Enter 触发（下方 v1.2 阶段一描述中的 debounceTimer 防抖逻辑已被替代，保留作历史记录）。

## 总体实施策略

书架快速检索功能分三个阶段实施。阶段一（书架内嵌搜索栏）和阶段二（命令面板）已在 v1.2 中完成；阶段三中的 AI 语义搜索已在 v1.3 中实现，搜索历史、拼音搜索等增强功能尚未实施。

## 阶段一：书架页内嵌搜索栏（✅ v1.2 已完成）

预计工作量：1 到 2 小时。这是必须实现的最小可用版本。

### 前端改动：ShelfView.vue（✅ 已完成）

在书架页面的标题栏（"我的书架"和"添加小说"按钮所在的行）下方添加了一个搜索输入框组件。搜索框使用 Element Plus 的 el-input 组件，placeholder 文字在普通模式下为"搜索书名或作者…"，AI 模式下为"用自然语言描述你想找的书…"。搜索框带有搜索图标前缀和清空按钮，右侧有普通/AI 语义搜索模式切换按钮。

搜索逻辑的实现方式：
- 使用 searchKeyword 响应式变量存储用户输入
- 使用 booksStore.searchMode（Pinia store 中的响应式变量）标记当前模式（client 或 server）
- 使用 aiSearchMode 响应式变量切换普通搜索/AI 语义搜索
- 使用 debounceTimer 存储防抖定时器引用
- onSearchInput 函数在每次输入时清除旧的定时器，设置一个新的 300 毫秒定时器
- 定时器到期后：AI 模式下调用 AI 搜索 API，普通模式下调用 clientSearch/clientFilter
- 搜索关键词和筛选标签同时生效（AND 逻辑），AI 模式下筛选标签自动隐藏
- 搜索结果中书名和作者的高亮匹配使用 v-html 渲染

### 前端改动：Pinia Store（✅ 已完成）

已在 Pinia Store 中新增以下状态和方法：
- allBooks 响应式数组：存储从后端一次性加载的全量书籍数据（page_size=200）
- filteredBooks 响应式数组：存储当前客户端过滤后的结果，书架页面渲染此数组
- searchMode 响应式变量：client 或 server，由总书籍数是否超过 200 本决定
- isClientMode 计算属性：便捷访问当前是否为客户端模式
- fetchAllBooks 异步方法：调用 getBooks API 一次性获取全量数据，自动判断模式
- clientSearch 方法：对 allBooks 做书名+作者双字段不区分大小写的字符串匹配
- clientFilter 方法：支持关键词 + 标记状态 + hasEpub + done 的多条件组合筛选
- resetFilter 方法：清空过滤，恢复全量书架

### 后端改动：book_service.py（✅ 已完成）

search_books 方法的查询逻辑已扩展：使用 SQLAlchemy 的 or_ 函数对 title 和 author 两个字段做 OR 条件匹配。

### 数据库优化（未实施）

由于当前数据量极小，尚未添加专门的搜索索引。如果未来需要，可以为 books 表添加覆盖 user_id、title、author、deleted_at 的复合索引。

## 阶段二：命令面板（✅ v1.2 已完成）

预计工作量：1 到 2 小时。

### 新增 CommandPalette.vue 组件（✅ 已完成）

已创建命令面板组件，类似 VS Code 的快速打开功能。核心设计：
- 使用 Element Plus 的 el-dialog 作为容器，宽度 560 像素，位于页面顶部 15% 视口高度处
- 对话框内包含大型搜索输入框，自动获取焦点
- 无输入关键词时显示最近阅读书籍（localStorage 持久化，最多 5 本）
- 有输入时从 allBooks 中客户端过滤匹配结果
- 支持键盘导航：↑↓ 移动选中项、Enter 跳转阅读器、Esc 关闭面板
- 搜索结果高亮匹配的文本片段
- 底部显示快捷键提示栏（↑↓ 导航 / Enter 打开 / Esc 关闭）

### App.vue 全局快捷键注册（✅ 已完成）

在 App 根组件中通过 window.addEventListener 注册全局键盘事件监听。当检测到 Ctrl+K（Windows/Linux）或 Cmd+K（Mac）时，唤起命令面板。当焦点在 input/textarea 元素中时不拦截，避免与浏览器搜索框等冲突。

## 阶段三：搜索体验增强（部分完成）

### AI 语义搜索（✅ v1.3 已完成）

在书架搜索栏新增"🤖 AI 语义"模式切换按钮，支持自然语言查询。用户输入描述性文字（如"最近看的那本修仙小说"），后端通过 AI 语义匹配返回关联书籍，含匹配原因和分数。

### 搜索建议与自动补全（未实施）

待未来实施：用户输入 1 到 2 个字符时就显示匹配建议列表。

### 搜索历史（未实施）

待未来实施：将用户最近搜索关键词存储到 localStorage，搜索框聚焦时展示。

### 拼音搜索（未实施）

待未来实施：引入 pinyin-pro 库，实现拼音首字母/全拼匹配中文书名。

### 高亮匹配（✅ v1.2 已完成）

搜索结果中书名和作者名与关键词匹配的部分以高亮颜色标记。

## 筛选标签设计（✅ 已实现）

书架页搜索栏下方已实现以下快捷筛选标签（横向排列的单选按钮组）：
- 全部：默认选项，显示所有书籍
- 已标记：仅显示星标书籍
- 抓取完成：仅显示状态为抓取完成的书籍
- 有 EPUB：仅显示已生成 EPUB 文件的书籍

搜索关键词可以与筛选标签同时生效，两者是 AND 关系。AI 语义搜索模式下筛选标签自动隐藏。
